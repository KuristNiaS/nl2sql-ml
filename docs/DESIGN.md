# 系统设计

## 目标与边界

系统面向《数据库设计文档》中的固定培训业务 Schema，在普通 CPU 上把中文查询转换成参数化 SQL Server `SELECT`。传统机器学习不直接逐词“写 SQL”；它负责处理表达变化，确定有限标签。表字段约束、日期计算、安全校验和 SQL 语法由确定性代码完成。

## 处理链路

```text
中文问句
  │
  ├─ 审核组合查询检测
  │    ├─ 年度×部门×月份×人均学习时长
  │    └─ 年度×多人×课程×最高/最低/平均成绩
  │
  ├─ 字符 1~5 gram TF-IDF + LinearSVC
  │    ├─ intent：list/count/aggregate/group_aggregate/top_n/cross_tab
  │    ├─ domain：12 个业务域
  │    ├─ table：111 张物理表
  │    └─ aggregation：sum/avg/max/min/count
  │
  ├─ Schema 语义解析
  │    ├─ 表/字段最长别名匹配
  │    ├─ 姓名、用户名、部门、课程、学习班等实体抽取
  │    ├─ 本表与跨表等值筛选值抽取
  │    ├─ 日期区间解析
  │    ├─ Top N 与排序方向解析
  │    └─ 安全关联路径搜索与条件消费检查
  │
  ├─ 组合语义 AST
  │    ├─ fact / measure / dimensions
  │    ├─ student_name IN / course_name / calendar_year
  │    └─ 歧义检查、事实表置信度门槛和明确拒答
  │
  └─ SQL Server 白名单编译器
       ├─ 方括号引用表和字段
       ├─ TOP、COUNT_BIG、GROUP BY、ORDER BY
       ├─ 普通查询仅使用审核白名单的 INNER JOIN
       ├─ 固定 KPI 模板可使用审核 LEFT JOIN 以保留零记录人员
       ├─ WHERE 参数使用 ? 占位符
       └─ 只允许生成一条 SELECT
```

这种拆分使模型无法创造目录之外的表或字段。SVM 即使预测错误，编译器仍会校验所有标识符和操作符；用户输入的值只进入参数数组。

## 设计书提取

原始 `.doc` 先转换为 `.docx`，然后按文档块顺序读取标题和 114 个 Word 表格对象。提取器执行以下步骤：

1. 根据章节标题划分 12 个业务域；
2. 从表前标题识别物理表名和中文名称；
3. 兼容 4、5、6 列以及无标题/无类型列的字段表；
4. 合并重复出现的同名表；
5. 将两张 OptionName/OptionValue 续表归入配置字典；
6. 应用设计书的全局 `SerialNo bigint NOT NULL IDENTITY` 修改；
7. 根据 PK/FK、字段名称和说明生成候选关系；
8. 从候选关系和约定外键中生成保守的查询关联白名单，并定义学员—课程、学员—学习班等桥接路径；
9. 输出 Schema 目录、实体词典、业务词典与提取质量报告。

提取结果是可审计的：原始文档副本、转换文档、完整目录和异常字段列表都保留在项目中。

## 模型

每个任务训练一个独立的 scikit-learn Pipeline：

```text
TfidfVectorizer(
  analyzer="char",
  ngram_range=(1, 5),
  min_df=2,
  max_features=140000,
  sublinear_tf=True
)
→ LinearSVC(class_weight="balanced", C=1.5)
```

字符特征不需要中文分词器，能覆盖中文、物理表名、字段缩写和混合数字。训练集按目标标签分层拆分 80%/20%。显示的 confidence 是将 SVM decision score 经 softmax 转换后的相对分值，不是经过严格概率校准的置信概率。

模型元数据保存数据量、随机种子、表数量、Schema SHA-256 指纹和语义层 SHA-256 指纹。加载时任一指纹不一致都会失败，防止使用过期模型或过期业务口径。

## 数据集

生成器先轮询所有物理表生成 60,000 条基础样本，保证每张表 540–541 条；再分别生成 4,000 条审核 KPI、4,000 条个人考试成绩组合和 4,000 条学生成绩排名改写，共 72,000 条互不重复问句。数据覆盖六种意图、表/字段别名、实体筛选、参数化 `IN`、多条件、日期范围、受控联表、跨表分组、排名、横表和组合语义 AST。当前包含 23,363 条联表、18,706 条多条件、34,360 条时间筛选、15,000 条跨表分组；8,000 条考试成绩语义样本均通过问句到 AST 的精确回放。

```json
{
  "question": "按状态统计学习班数量",
  "intent": "group_aggregate",
  "domain": "training",
  "table": "Study_Class_Info",
  "aggregation": "count",
  "metric_column": "__none__",
  "dimension_column": "Status",
  "plan": {},
  "sql": "SELECT [Status] AS [Status], COUNT_BIG(*) AS [record_count] FROM [Study_Class_Info] GROUP BY [Status];",
  "params": []
}
```

有歧义的短表别名不会用于训练。例如设计书把 `tk_lx` 标题写成“题库集表”，而字段说明明确它表示“节（题库）”；目录保留原始标题，训练词典则区分“题库集”与“节题库”。

## 确定性语义规则

- “按、每个、各”优先识别为分组查询；
- “数量、总数、记录数”在分组语句中编译为 `COUNT_BIG(*)`；
- “平均、合计、最大、最小”映射到白名单聚合函数；
- “前 N、Top N、排名”识别为排名；数值排名无显式聚合时默认 `SUM`，非数值排名默认 `COUNT`；
- 今天、昨天、本月、上月、今年、去年及最近 N 天转换为左闭右开的日期区间；
- 姓名、用户名、部门、课程、学习班、线下培训和能力实体必须映射到明确字段；实体位于其他表时只搜索白名单路径；
- 学员—课程、学员—学习班等多对多关系只能经过显式桥接表；默认不从一个事实表反向扩散到另一个事实表；
- 问句中出现“张三创建的课程”等角色敏感条件但 Schema 没有明确安全路径时，系统直接拒绝，不生成遗漏条件的宽查询；
- “年度/全年 + 部门 + 每月/逐月 + 人均 + 学习时长”识别为 `cross_tab` 审核报表，不退化成部门计数；
- “年度 + 多名学员 + 各自/分别/每人 + 课程 + 最高/最低/平均成绩”解析为显式 AST，不让分类器直接选择整条 SQL；
- 多名学员但未说明分别还是合并统计时拒绝生成；目标事实表置信度过低时也拒绝生成；
- 明细查询默认 `TOP (100)`，用户 Top N 上限为 1000。

## 审核 KPI：部门逐月人均学习时长

- 事实表：`Student_Course_Log`；时长为有效 `EndTime - BeginTime`；
- 部门与人口表：`Student_Info`，通过 `StudentId = Id` 关联；
- 分母：当前 `Status=1` 的启用学员数，包括没有学习日志的人员；
- 分子：自然年内各月有效课程学习会话秒数合计，最终换算为小时；
- 输出：一行一个部门，横向生成 1–12 月十二个指标列；
- 年份、状态均参数化，月号与字段来自固定模板；
- 设计书没有部门/在职状态历史，历史记录按学员当前部门归属，各月使用当前启用人数；跨月会话按 `BeginTime` 归入开始月份。

“人均”的分母、事实来源和时间归属都是业务定义，不能让分类模型或神经网络自行猜测。未匹配到审核规则的同比、环比、中位数、占比、人均或交叉表需求会拒绝生成。

## 审核语义：学员考试成绩聚合

- 事实：`clerk_kscj`，成绩字段为 `Cj`，时间字段为 `clerk_ks_btime`；
- 范围：固定筛选 `Clerk_ks_status=1` 且 `Cj IS NOT NULL`；
- 学员：`clerk_kscj.ExamStartId → Exam_Start.Id → Student_Info.Id`，姓名筛选编译为参数化 `IN`；
- 课程：`clerk_kscj.Tk_cl_id → tk_cl.Tk_cl_id → Course_Info.Id`，并限定 `tk_cl.SiteType IN (1,3)`；
- 聚合：只允许 `MAX`、`MIN`、`AVG`，按 `Student_Info.Id, ActualName` 分组；
- 年份：转换成 `clerk_ks_btime` 上左闭右开的自然年范围；
- 类型假设：设计书中 `tk_cl.SiteID` 是 `int`、`Course_Info.Id` 是 `varchar(50)`，编译器使用 `CONVERT(varchar(50), SiteID)`。该关系和执行性能必须在真实库核验。

解析结果先形成 `fact / measure / dimensions / filters` AST，再由专用白名单编译器生成 SQL。这样新增同义表达只需要扩展解析词典或训练样本，而事实表、连接路径和指标口径仍由审核配置控制。

### 学生成绩排名

排名 AST 在相同成绩事实之上增加 `ranking.limit` 和 `ranking.order`，支持：

- 自然年筛选；
- `Student_Info.Department` 部门/处/中心筛选；
- 指定课程、所有课程（只含 `SiteType IN (1,3)`）或所有考试；
- 按学员 ID 与姓名分组计算 `AVG/MAX/MIN(Cj)`；
- SQL Server `TOP (N)` 和稳定的分值、姓名、ID 排序。

设计书的学员表没有专业、年级、学院或班级字段。解析器识别到这些条件时会明确拒绝，不能把条件丢掉，也不能误用仅存在于讲师表的专业字段。

## 安全边界

- 只接受目录中的表名和字段名，并使用 SQL Server 方括号引用；
- 每个 JOIN 的左右表和字段组合必须存在于 89 条查询关联白名单中；
- 只允许 `=、>、>=、<、<=、<>、LIKE、IN、IS NOT NULL`，其中 `IN` 元素数量受限并逐个参数化；
- 值一律使用 `?` 参数，不参与 SQL 字符串拼接；
- 编译结果必须以 `SELECT` 开头且只能包含一条语句；
- 当前命令行只翻译，不直接执行数据库查询；
- 生产集成仍应使用只读账号、超时、最大返回行数和审计日志。

## 评估

评估分三层：

1. 分类测试集：检查四个 SVM 标签任务；
2. 人工验收集：检查问句到语义计划和 SQL 的完整链路；
3. 单元测试：检查 Schema 规模、全表覆盖、参数化、联表白名单、多跳路径、远程分组、组合 AST、安全拒绝、日期区间和双指纹绑定；
4. 组合数据回放：逐条重新解析 8,000 条成绩聚合与排名改写，并与保存的语义 AST 精确比较；
5. 对抗测试：200 条由考试管理员、教务管理员、教师、培训负责人等角色提出的 21 种风格问句，严格顺序执行并首错即停。

合成模板的分类准确率通常高于真实用户问法。生产验收应新增一批不参与模板和训练的真实问句，并在只读测试数据库上对结果集做执行正确率核验。

## Schema 变化

- 数据行变化不影响模型；
- 词典同义词变化通常只需更新 JSON 并重新验收；
- 表、字段、类型、语义事实关系或主要业务口径变化必须重新生成数据并训练；
- 新的多表报表应先将经过人工审核的 JOIN 路径、连接基数和指标口径写入受控配置，不能仅依靠 SVM 猜连接。

后续最有价值的改进是收集真实问句、增加拒识阈值与澄清提示，并为高频跨表报表定义显式语义视图。
